# Tracer product brief

## Direction and evidence
Tracer helps documentary editors, writers, and storytellers understand local footage, find a spoken moment, assemble selects, and deliver an editable sequence.

The current conversation is the primary evidence. The user chose a simple Storyline with unlimited stacking, a separate transcript editing workspace, Library-based multi-selection, native Windows imports, local processing, and compact delivery. Their latest palette decision supersedes the earlier warm-paper experiment: use Tracer's dark colors.

The related task “Find Paperclip Image” confirms the original transcript-workspace intent; the reference was later supplied in this conversation as Paper Edit. Retrieval of “Plan Tracer v2 video library” failed, so no additional decisions are inferred from it.

## Current outcome
Make the Library → Paper Edit → export journey dependable and readable. Success means selecting videos across searches, retaining authored edits after revisiting a source, reading passages without excessive blank space, and exporting the selected order without changing the document mid-job.

## Protected scope
Keep the five workspaces, dark palette, manual notes and drawing, local media references, simple Storyline and compact Delivery. Avoid a new project-management system, generative story claims, framework migration, native Premiere project promises, or deleting source media.

## Measures
- Checked footage survives search changes and no-match searches.
- Authored text, notes and timing survive a later transcription run.
- Export uses an immutable document snapshot and rejects empty or invalid ranges.
- Short passages use compact rows; long passages expand for readable editing.

These are acceptance criteria, not claims of measured user adoption. Cross-source paper stories and accurate multitrack audio preview remain future work.
